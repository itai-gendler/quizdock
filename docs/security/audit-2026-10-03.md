# Global audit — 2026-10-03

**Release under review:** `v0.13.1` (`dev` == `main`, `c0cf06c9`)
**Scope:** application security, deployment and supply chain, backend and frontend
robustness, accessibility, i18n, documentation drift, dead code.
**Remediation shipped in:** `v0.13.2`, unless the table says otherwise.

Point-in-time snapshot. What is still open lives in [`docs/tech-debt.md`](../tech-debt.md),
not here.

## Method

- Seven read-only reviews in parallel: authentication and rights, untrusted input,
  deployment and supply chain, backend, frontend, documentation, dead code.
- Non-destructive reproductions on the dev stack; scans (osv-scanner, `pnpm audit`, knip)
  and cost measurements (Levenshtein, MP4 sniffing, archiving, export) in throwaway
  `node:24` and `postgres:16` containers.
- Every fix came with a test that fails without it, unless stated.
- Paths: `BE/` = `apps/backend/src/`, `FE/` = `apps/frontend/src/`.

## 1. Application security

### High

| ID | Finding | Status |
|---|---|---|
| S1 | A player could freeze the whole server with one text answer: `player:submit` checked neither type nor length, every resend was scored again (before the first-answer check), and `lenient` scoring is a length × length Levenshtein. Measured: ~0.8 s of CPU per message, up to 16 s. | Fixed: answers validated by type and size (text ≤ `ANSWER_TEXT_MAX`, no NUL), uniqueness checked before scoring, early exit in `lenientMatch` when the lengths alone exceed the tolerance |
| S2 | The CSRF check (`Sec-Fetch-Site`/`Origin`) only applied to paths starting exactly with `/api/`; Express ignores case, so `/API/v1/...` reached the same routes. Reproduced: an admin operation from another origin of the same site. | Fixed: every unsafe method checked, whatever the path; non-JSON bodies refused on JSON routes |
| S3 | Without `OIDC_AUDIENCE` (the default), tokens were not bound to QuizDock, and an ID token was accepted as a Bearer token (reproduced). The ID token travels in the logout URL (`id_token_hint`), so it stays in the browser history. | Partly fixed: ID tokens refused. Binding to the client when no audience is set is open, see tech-debt |
| S4 | Media uploaded before v0.10 were served with the type the browser declared: a crafted SVG could run on the application's origin. Not reproduced (no such row in the dev base). | Fixed: only recognised types served as is, the rest as an attachment; `default-src 'none'; sandbox` on the media routes |
| S5 | A NUL byte in a nickname or an answer made archiving fail (PostgreSQL refuses NUL in `text` and `jsonb`); without a host, silently. | Fixed: control characters stripped from nicknames, room names and comments; NUL refused in answers |

### Medium

| ID | Finding | Status |
|---|---|---|
| S6 | No rate limit on socket events: `player:join` replayable on one socket (ghost players), room-wide broadcasts multiplied, an unbounded `media:ready` index creating Redis sets; production Redis without `maxmemory`. | Fixed: a message budget per socket, one join per socket, bounded steps. No cap on players per room (product choice) |
| S7 | An unverified OIDC e-mail was a unique key: squatting (a CLI role grant by e-mail promoting the squatter) and lockout (an account recreated in the IdP got 409 on every request). | Fixed |
| S8 | The PIN attempt limit could be bypassed: without `TRUST_PROXY`, any private-address peer could forge `X-Forwarded-For`; in IPv6, a /64 counted as many addresses. | Fixed: counted per /64 in IPv6. No global cap (it would let anyone block every connection) |
